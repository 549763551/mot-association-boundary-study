## 1. 研究动机

实验 A 的 `oracle-detection` 口径把检测器因素完全隔离掉了（`DetA ≈ 0.97`），因此即使得到负结果，也不能回答一个更要紧的问题：**真实检测器噪声下，精细关联到底在什么条件下才值得部署**。设计实验 B 之前，需要先核实哪些位置已有先行工作。

系统化查新（2 路综述式检索 + 9 组定向检索 + 3 篇原文/摘要抓取）的结果如下：

| 待核实的空白 | 核实结果 |
|---|---|
| 连续噪声轴无人涉及 | **不成立**。DiffusionTrack (arXiv 2308.09905) 已用 `B_det=(1−α)B_det + α·B_noise` 扫连续 α 并报 MOTA 曲线 |
| 「噪声强度作自变量」是空白 | **部分被占**。已有 Robustness Score 与 Breaking Point 定义 |
| PPLR 用于在线 MOT 无人涉及 | **不成立**。CropTrack 已把 k-reciprocal + Jaccard 用在在线逐帧关联；PPLR 的 Cross Agreement Score 原文核实就是 Jaccard |
| oracle 分析是新的 | 已有 Tracktor / QDTrack / PigTrack |
| 帧级门控、弃权是新的 | 已有 When-to-Extract、Deep OC-SORT、AAI、U2MOT、LLTrack、Sentinel |
| 检测 vs 关联谁更值钱 | Ma et al. (arXiv 2609.22291) 已定量：检测器改进 >10%，精细关联 <5% |

另有两处事实核对：VLA-ReID 用的是 BEE24 蜂群数据集，不是行人 MOT；「相对残差 × 显式分模块 × Jaccard × 一致性作弃权置信度」由已有构件组合而成。

**结论**：机制层面的新意空间有限，研究问题因此定位于方法学边界与可预测性。

## 2. 「无人做」被收敛成可证伪的组合判据

无法证明世界上无人做过（未检到 ≠ 不存在）。能站住的主张是：在可检索范围内，**未检到同时满足四条的工作**——

- (a) 检测噪声按**正交分量**连续标定扫描；
- (b) 响应量是「精细关联相对 IoU 基线的**边际关联增益**」，而非 tracker 整体指标；
- (c) 形式化定义并测绘收益的**符号翻转边界**；
- (d) 给出**评测前、无需标签**预测收益符号的判据，并做留一外部验证。

最接近的竞品各缺 2–3 条。因此研究定位**不在机制，在方法学与结论**：把「这套关联值不值得上」从事后跑分，变成可标定、可测绘、且可事先预测的量。交叉一致性弃权、差异指纹、分模块 Jaccard 全部作为**被测机制 / 对照**，不附带首创性主张。

## 3. 预注册设计

- **自变量** `Θ = (σ_loc, β, λ, τ)`：框抖动（按目标高度归一）、漏检率、虚检率、失败状态的时间相关长度。用官方 `det.txt` 反解 `Θ̂`，把注入坐标对齐到真实检测器。
- **响应量** `ΔAssA = AssA(s) − AssA(SORT-IoU)`，配 `ΔIDSW`、`IDF1`。**主指标不用 HOTA/MOTA** —— 噪声主要打 `DetA`，几何平均会淹没关联差异。
- **三个边界量**：`η*_0`（边际收益归零/首次变号）、`η†`（收益被检测退化吞没）、`η_flip`（开始主动制造 ID 切换）。
- **三条研究问题**：RQ1 收益曲面形状与边界；**RQ2（主）** 仅从检测输出可观测量预测 `ΔAssA` 符号；RQ3 文献中的关联增益有多少其实来自检测噪声水平。
- **统计**：cluster bootstrap（1000 次，按序列重采样）95% CI + Holm 校正；探索子集拟合、确认阶段一次性验证；Phase 0 冻结后不许调阈值；注入 / 官方 det 两个口径都报。
- **与帧级门控工作的分界线**：它们回答「这一帧用不用 ReID」，这里回答「这个场景要不要部署」。

## 4. 设计决策

预注册阶段确定的五项决策：

| # | 决策 | 理由 |
|---|---|---|
| 1 | 主研究问题 = **边界 + 可预测性**，不以提出新的门控机制为目标 | 查新后可辩护的研究定位，两种结果方向均可产出结论 |
| 2 | MOT17 + DanceTrack 主分析，**MOT20 留作留一外部验证** | DanceTrack 用 GT 注入绕开「无官方 det」；MOT20 不参与拟合 |
| 3 | A5（set-relative 残差）**纳入但降为探索性**，不进 Holm 族 | 强化 RQ3 归因，又不增加多重比较负担 |
| 4 | 两阶段抽样 + Phase 0 **SHA-256 封装冻结** | 每阶段校验，避免口径漂移 |
| 5 | 立即写配置与代码 | — |

额外收紧两处：留一噪声分量族降为次要读出（样本小、CI 宽易假阴性）；判据 `P` 只用 ≤8 特征的逻辑回归，系数可直接回答 H3。

## 5. Phase 0/1 的标定结果（在任何 GPU 实验之前）

从官方 `det.txt` 反解 `Θ̂`，得到三条影响方案的事实：

1. **可标定的只有 TRAIN 序列**：MOT17 21 个 / MOT20 4 个，不是设计稿写的 42 / 8（后者含无公开 GT 的 TEST）。
2. **真实噪声画像**：框抖动中位数仅 **0.020**，漏检率中位数 **0.432**，连续漏检游程中位数约 **10 帧** → 主要噪声是**时间相关漏检**，不是框位置误差。原设计的极端档位不合理。
3. 纯分位数锚定会整段跳过 `β ∈ (0, 0.39)`，而那正是最可能有正收益窗口的区间 → 改为 `hybrid_v1`：设计稿低档 + 一个实测分位数锚点 + 预设极端上界，得 **28 个唯一条件**。

**两项实现要点**：

- `geometry_keyed_v1`：只有 `σ_loc > 0` 会改变框几何；β 删框、λ 加框、τ 改时间相关性时，存活 TP 框与 GT 逐位相同，特征可直接复用 → **28 个条件里仅 9 个需重抽**（原估约 30 GPU·h 大幅下降）。
- `src_gid` 旁路：注入后身份回映射使用对跟踪器不可见的原始 gid 通道，17/17 自检通过（完美跟踪器 IDSW=0、人为注入 2 次切换恰数出 2）。

**跨源校验**：MOT17 原始归档与公开镜像重打包数据，25 个序列的 `Θ̂` **逐字段零差异**（`CROSS_SOURCE_CALIBRATION_OK`）。
